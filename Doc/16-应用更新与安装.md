# 16 · 应用更新与安装

[返回文档中心](README.md) · 基线：1.3.4

## 1. 用户流程

设置中的“应用更新”显示当前版本、检查状态、自动检查开关和手动检查按钮。发现较新的正式版本后提供版本号、公告、包大小和“下载并安装”。阅读器及详情页不展示自动检查对话框，返回主页后才可显示；手动打开设置可以重新查看被关闭的公告。

默认允许启动检查，但两次自动检查至少间隔 24 小时。时间在发起请求时记录，因此无网络或限流也不会在每次打开时重复请求。手动检查不受此间隔约束。关闭开关不会删除安装包，也不改变漫画预加载的 Wi-Fi 偏好。应用更新下载必须由用户点击，可能使用移动网络。

下载进度以字节计算，显示百分比，约 200 ms 才更新一次，避免逐块刷新 Compose。用户可以取消并重试，也可关闭公告后稍后查看。下载成功且应用在前台时调起系统安装；未授权安装来源则打开针对 ComicReader 的系统授权页。授权返回后继续安装，拒绝后仍可再次操作。

系统安装页面必须由用户确认，应用不进行静默安装。Samsung 的系统策略可能限制安装来源，需要按系统提示处理。覆盖安装沿用原包名及签名，不卸载，不清除书库。1.3.3 及以前没有应用内更新入口，需要先手动安装此版本。

## 2. 模块与状态

- [AppUpdates.kt](../app/src/main/java/com/arnolee/moye/AppUpdates.kt)：UpdateVersions 比较版本；AppRelease 验证发布元数据；UpdateRepository 请求和下载；UpdateInstaller 验证及构建安装 Intent；AppUpdateController 保存 UI 状态和任务。
- [UpdateScreen.kt](../app/src/main/java/com/arnolee/moye/UpdateScreen.kt)：设置卡片、公告、进度、取消／重试／安装按钮。
- [MainActivity.kt](../app/src/main/java/com/arnolee/moye/MainActivity.kt)：启动检查、RESUMED 期间消费安装请求、系统安装来源授权结果。
- [update_paths.xml](../app/src/main/res/xml/update_paths.xml)：FileProvider 只映射 files/updates，不公开漫画目录或数据库。

AppViewModel 持有 controller，屏幕重建不重启下载。checking、downloading、downloaded、bytes、status、release 组成状态；task 防止重复检查／下载。installRequested 是单次安装请求，只有 RESUMED 的 Activity 消费。准备安装另有去重标记，防止连点同时打开多个系统页面。

## 3. 版本与数据源

固定读取 `https://api.github.com/repos/hzxslzb/ComicReader/releases/latest`，无需 GitHub 账号、Token 或自建服务器。只接受非 draft、非 prerelease 的 `v主.次.补丁` 或无 v 前缀数字版本。按三个整数逐段比较，避免将 1.10 误判为低于 1.9；相等、较旧、预发布或异常版本不提供升级。

附件必须唯一匹配 `ComicReader-{version}.apk`，下载地址必须对应本仓库、本标签和该文件名。安装包大小上限 150 MiB，GitHub 元数据上限 2 MiB；摘要必须是 64 位 SHA-256。缺少 APK／摘要时提示稍后重试，不选择源码 ZIP 或其他 APK。公告仅作为文本显示，不执行 HTML 或脚本。

GitHub 的 403／429 显示限流提示，其他异常显示可重试状态；失败不影响书架及阅读。网络客户端独立于漫画源，不添加漫画 Referer 或图片 CDN 重试策略。

## 4. 下载与校验

仅在用户点击时下载，写入 files/updates/update.part，读取过程中累计长度和 SHA-256，超过声明长度立即停止；结束时长度与摘要必须都匹配。下载和文件验证不运行在主线程。

通过编码内容校验后，再读取 APK 的 PackageInfo：包名与当前应用一致，versionName 与发布信息一致，versionCode 必须严格大于当前版本，签名证书集合必须与当前安装包相同。Debug 包使用独立包名，因此不能被官方 Release APK 覆盖；自签名分支也不能通过官方包的签名比较。

验证通过后将 part 改名为 update.apk，再保存 release.json；安装前重复校验，防止下载完成后文件变化。异常或取消时清理 part；已验证的 APK 仅向系统安装器授予临时 URI 读取权限。

## 5. 进程、文件与权限

新增独立 SharedPreferences `updates`：autoCheck（默认 true）、lastCheck（毫秒）。书库数据库版本仍为 1，原有阅读设置及下载文件不迁移。安装包与元数据位于 files/updates，与 files/chapters 隔离。

重启后会读取已完成包的元数据并重新验证，可继续安装，但不自动唤起安装器。升级后旧缓存版本不再较新时删除 updates 目录。未完成的下载不做断点续传；应用进程被终止后需要重新下载。此下载不使用新的保活服务，不保证在进程终止后继续；没有定时后台轮询或自动下载。

Manifest 增加 REQUEST_INSTALL_PACKAGES 和不可导出的 FileProvider，授予的仅是安装文件 content URI。没有新增广泛存储权限，没有更改互联网及漫画下载服务的权限。

## 6. 验证与维护

JVM 用例 AppUpdateTest 覆盖版本数字比较、正式附件选择、异常版本、错误来源、缺少摘要及大小边界。设备 AppUpdateFlowTest 覆盖公告流程、设置持久化、错误重试、下载摘要／长度、旧版本拒绝、安装 URI 和路径范围。章首手势另由 ChapterAdvanceTest 覆盖，实际发布验证见 [TESTING.md](../TESTING.md)。

未来发布仍需增加 versionCode、正确命名 APK 并上传到正式 Release；先完成附件上传再对外发布，可避免用户读取到缺少 APK 的短暂状态。仓库迁移、包名或签名变更需显式改造，不应通过移除校验规避。

接口依据：[GitHub Releases API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)、[Android FileProvider](https://developer.android.com/reference/androidx/core/content/FileProvider)、[Android 安装来源授权说明](https://android-developers.googleblog.com/2017/08/making-it-safer-to-get-apps-on-android-o.html)。
