# 15 · 设计决策与演进计划

[返回文档中心](README.md)

本章前半部分记录现有代码体现的取舍，后半部分是**尚未实现的建议**，不构成版本承诺或交付时间表。

## 1. 原生呈现数据源内容

**当前选择**：OkHttp 获取页面，Jsoup 与受约束的解码器解析数据，Compose 展示，不使用 WebView 执行网页。

**收益**：界面可统一主题、阅读手势和折叠屏布局；不加载页面广告脚本；下载和历史可以围绕稳定领域模型实现。

**代价**：页面选择器、分页协议和打包数据结构变化需要维护解析器。不能借助浏览器完整执行站点脚本自动获得所有新行为。

**维护原则**：增加解析夹具和错误分类，保持不执行远程脚本的边界。新增站点应先定义数据源接口和身份空间，不能直接把另一站 ID 混进现有数字主键。

## 2. 单 app 模块与直接依赖

**当前选择**：单 Gradle app 模块；Application 持有 Store 与 Source，ViewModel 组织业务，Compose 屏幕消费状态；没有 Hilt、Room、导航框架或自建服务端。

**收益**：项目规模较小时，路径直接、可追踪、构建和调试成本较低。

**代价**：AppViewModel 与部分屏幕文件承担较多职责；复用与隔离需要纪律，不能把当前概念分层误写成已经存在多个模块。

**演进触发点**：新增多个来源、多人长期维护、复杂导航或后台调度时，再拆出清晰接口与独立组件；不以堆叠框架作为功能完成标准。

## 3. SQLite 元数据与私有文件分离

**当前选择**：四张 SQLite 表管理书目、进度、清单、任务；Manga 和 ChapterPages 部分字段以 JSON 保存；图片单独存文件。

**收益**：关系约束保持简单，章节图片不进入数据库大字段；删除某章下载能独立于书架和历史。

**代价**：JSON 缺乏独立 schema 版本；复杂检索和迁移需要手工实现；数据库事务与文件 rename 不能跨介质组成一个事务。当前 onUpgrade 未实现未来迁移。

**不变条件**：不因卡片缺目录覆盖完整详情、不因删除下载删除历史、不为解决迁移问题清库。详见 [09](09-数据模型与持久化.md)。

## 4. 原始图片页码作为历史基准

**当前选择**：用 `(book, chapter)` 保存该章最近原始图片索引，不保存双页组号、纵向像素或倍率。

**收益**：三种模式、单双页和折叠窗口之间容易保持准确身份；各书各章互不覆盖。

**代价**：超长条漫重新进入只能恢复到图片，无法精确到条漫内部已读位置；没有完整逐页访问轨迹。

**潜在扩展**：可增加归一化页内位置，但需说明图片尺寸变化、单双页切换和旧版兼容；不能直接存屏幕像素并假设换屏后仍正确。

## 5. 前台阅读与后台预取共享请求

**当前选择**：ReaderChapterLoader 用进行中的请求表和等待者计数去重；前台先加入，后台再取消。页面请求另用 generation 防止旧异步结果覆盖新页面。

**收益**：用户切章可以复用已启动的工作；关闭预加载不会误杀已被前台依赖的章节请求；旧 finally 不再错误结束新 loading。

**代价**：缓存、等待者、取消和页面状态是多个独立生命周期，改动顺序容易引入竞态。只测成功加载不足以证明正确。

**必须维持的测试**：旧请求晚到、最后一个后台等待者退出、前台加入后后台退出、失败后重新进入、离开阅读器清理。详见 [07](07-预加载缓存与网络策略.md)。

## 6. 临时缓存与永久下载分离

**当前选择**：Coil 临时图片缓存限制 150 MiB；永久离线下载存在 files/chapters，数据库记录任务。预加载不会创建下载任务或写下一章阅读记录。

**收益**：预加载不会把未读章节标记为已读，也不会把短期浏览变成永久存储；用户可显式管理离线内容。

**代价**：同一图片可能在临时缓存和永久文件中各有一份；只靠预加载不能保证离线完整。

**潜在扩展**：统一下载缓存复用必须同时解决完整性、权限、淘汰和来源身份，不能简单把 Coil 缓存目录当永久书库。

## 7. 稳定图片缓存键

**当前选择**：阅读图片磁盘／内存 key 使用漫画、章节、索引、图片路径，排除临时 query 和候选 CDN host。1.3.3 图片预取按窗口增量更新且跳过位图解码；显示时按实际宽度分档解码。

**收益**：预取与全尺寸显示、镜像切换和签名刷新能够复用同一编码图片，避免每次签名变化都重新下载。

**代价**：如果远端在同一路径替换图片，客户端不一定立即感知内容更新；当前没有按单张图片版本指纹主动失效的机制；设置中提供整体清理阅读图片缓存的入口。

**维护要求**：新增数据源或路径规则时重新评估碰撞和更新语义；不能删除漫画／章节维度只按索引缓存。

## 8. 整页续传与同目录临时落盘

**当前选择**：逐张写 `.part`，校验大小和图片边界，sync 后在任务仍有效时 rename；已完成图片跳过，未完成图片重新下载。

**收益**：实现清晰，正常情况下阅读器不会读到未完成最终文件；暂停、删除和提交之间有锁保护。

**代价**：超大单图中断需要重下；available 只检查非空，不能检测所有事后损坏；没有总容量限制。

**潜在扩展**：优先补文件完整性与空间预检，再评估是否真的需要 Range 字节续传。没有稳定服务端 Range 语义时不能只通过追加文件实现。

## 9. 窗口适配而非机型分支

**当前选择**：按 dp 宽高决定导航、分栏和双页。

**收益**：Fold7 内外屏、横屏、分屏和其他大屏可以共用规则。

**代价**：无法感知铰链遮挡、半折角度和厂商特殊连续性行为。模拟器尺寸覆盖不能替代实体设备验证。

**潜在扩展**：在确有硬件需求和测试条件时引入窗口姿态信息，维持原始页码映射不变。

## 10. 同包名与同签名升级

**当前选择**：名称与图标可变化，包名 `com.arnolee.moye`、数据库及下载目录保持稳定，正式版本沿用同一证书。

**收益**：用户可以覆盖升级保留数据。

**代价**：内部旧名继续存在；签名私钥成为发行连续性的关键资产，必须仓库外备份。不能为了改名美观牺牲升级兼容。

## 11. 已知缺口与建议优先级

以下均为建议，不是当前功能列表。

| 优先级 | 事项 | 解决的问题 | 建议验收标准 |
| --- | --- | --- | --- |
| 高 | 建立数据库迁移框架与旧库夹具 | 未来 schema 变更会触发未实现 onUpgrade | 至少覆盖旧版逐版本迁移、收藏历史下载一致性 |
| 高 | 可控的数据导出／导入 | 卸载、换机无恢复渠道 | 明确版本、完整性、覆盖策略和私有数据保护 |
| 高 | 更细错误分类与可脱敏诊断 | 网络、解析、取消混淆 | UI 可区分，日志不泄露签名参数 |
| 高 | 下载文件完整性和缺失修复 | complete 状态与实际文件可能不一致 | 缺页／损坏后可重下且不丢历史 |
| 中 | 把频繁 Store IO 从 UI 路径隔离 | 大书架／历史下潜在卡顿 | 测量主线程耗时，保持原有状态一致性 |
| 中 | 审计搜索／详情请求所有权 | 共用 loading/error 时存在旧请求覆盖风险点 | 先建立可复现测试，再加代次或独立状态 |
| 中 | 下载空间预算与清理界面 | 无总量上限、空间不足体验弱 | 展示真实占用、保留空间、明确删除范围 |
| 中 | 低 API、低内存与实体 Fold7 验证 | 当前模拟器覆盖不足 | 记录设备、系统、复现步骤与结果 |
| 中 | 长队列与服务中断恢复测试 | 厂商／系统终止下载 | 无丢任务、无伪完成、用户可明确继续 |
| 后续 | 页内阅读位置、更多来源、姿态布局 | 更精细阅读与设备体验 | 定义兼容模型后逐项实现 |

其中搜索／详情的异步风险属于代码审查发现的待验证点，并非宣称已经复现一个新缺陷。不要把推测写进 Release “已修复”列表。

## 12. 改动评审检查表

1. 新功能是否改变原始页码、书籍身份或缓存 key？
2. 取消一个请求是否可能影响仍在等待的前台用户？
3. 旧异步结果是否能写入新页面的 loading/error？
4. 预加载是否偷偷变成整章／整书下载，或修改阅读历史？
5. 暂停／删除时临时文件能否被错误提交？
6. 断网时使用的是完整永久下载，还是仅仅碰巧命中缓存？
7. 包名、签名、schema、文件目录是否兼容已安装用户？
8. 宣称的折叠屏、离线和升级能力是否有对应实际验证？
9. 文档是否明确区分当前实现和计划？

保留这些约束，比单独增加功能按钮更能保护现有用户的阅读体验和数据。
