# 09 · 数据模型与持久化

[返回文档中心](README.md) · 关联：[历史](05-书架详情与阅读历史.md)、[下载](08-下载与离线阅读.md)、[升级](12-开发构建与发布.md)

## 1. 存储职责与身份

正式应用的 `applicationId` 为 `com.arnolee.moye`，数据库为 `library.db`，schema version 为 **1**。应用名改为 ComicReader 没有改包名。Debug 使用独立包名 `.debug`，有独立沙箱，不能直接读正式版数据。

持久数据分布在 SQLite、SharedPreferences 和应用私有文件三个区域。图片临时缓存单独位于 `cacheDir/images`。实现入口：[Models.kt](../app/src/main/java/com/arnolee/moye/Models.kt)、[LibraryStore.kt](../app/src/main/java/com/arnolee/moye/LibraryStore.kt)、[AppViewModel.kt](../app/src/main/java/com/arnolee/moye/AppViewModel.kt)。

## 2. 领域模型

| 模型 | 主要字段 | 语义 |
| --- | --- | --- |
| `Manga` | id、title、cover、author、summary、category、latest、chapters | 搜索卡片和完整详情共用类型；卡片可能没有章节 |
| `Chapter` | id、title | 章节身份，不含图片清单 |
| `ChapterPages` | mangaId、chapter、paths、query、prevId、nextId | 图片路径和请求参数，以及前后章 ID |
| `SearchResult` | books、hasMore | 一页搜索结果及继续加载标记 |
| `Progress` | bookId、chapterId、chapterTitle、page、total、time | 一个章节最近的阅读断点 |
| `Download` | bookId、chapterId、title、state、done、total、error | 一个章节下载任务；key 为 `bookId/chapterId` |

ID 用字符串存储，避免把站点 ID 当作可计算业务数值。图片页码采用从 0 开始的原始图片索引；UI 显示时加 1。横向双页的“组号”不是历史记录页码。

`ChapterPages.url(index, host)` 使用 HTTPS 和 `$host.hamreus.com` 构造图片地址，把 `paths[index]` 作为编码路径、`query` 逐项加入查询参数。默认 host 为 `eu`。`referer` 为该漫画的章节页面 URL。图片查询参数属于可过期数据，不应硬编码到客户端或公开日志中。

## 3. SQLite 完整结构

当前是 **四张表**，没有独立的收藏表或“每本最近阅读”表。收藏是 books 的字段；每本最新进度从 progress 查询得到。

```sql
CREATE TABLE books(
    id TEXT PRIMARY KEY,
    data TEXT NOT NULL,
    favorite INTEGER NOT NULL DEFAULT 0
);
CREATE TABLE progress(
    book TEXT, chapter TEXT, title TEXT,
    page INTEGER, total INTEGER, time INTEGER,
    PRIMARY KEY(book, chapter)
);
CREATE TABLE manifests(
    book TEXT, chapter TEXT, data TEXT,
    PRIMARY KEY(book, chapter)
);
CREATE TABLE downloads(
    book TEXT, chapter TEXT, title TEXT, state TEXT,
    done INTEGER DEFAULT 0, total INTEGER DEFAULT 0,
    error TEXT DEFAULT '', created INTEGER,
    PRIMARY KEY(book, chapter)
);
```

代码未声明外键、级联删除或额外业务索引。不能假设删除某表记录会自动删除其他表或文件。关联关系由调用方和 Store 方法维护。

### 3.1 books

- `data` 是 `Manga.json()` 的 JSON 字符串。
- `favorite` 为 0 或 1，`toggleFavorite` 使用 `1-favorite` 切换。
- `putBook` 使用 `ON CONFLICT(id) DO UPDATE SET data=excluded.data`，更新详情不会重置收藏。
- 如果新数据的章节列表为空且已有旧记录，保留旧的整条 Manga，避免搜索卡片抹掉离线所需的目录；这也意味着此时卡片中的新标题或封面不会单独覆盖旧详情。
- `books()` 按 rowid 倒序返回；不要将此排序解释成最近阅读顺序。

### 3.2 progress

联合主键 `(book, chapter)` 保证不同漫画、不同章节独立。`saveProgress` 拒绝 `total<=0` 和越界页码，之后 `INSERT OR REPLACE`，时间为 `System.currentTimeMillis()`。

本书最新断点查询：

```sql
SELECT * FROM progress
WHERE book=?
ORDER BY time DESC, rowid DESC
LIMIT 1;
```

时间相同时，rowid 用于本书内的次序补充。最近阅读首页为每本漫画选择该规则下的最新记录，再按时间排序；不同书完全同毫秒时，没有额外跨书排序承诺。系统时钟回拨也可能影响时间先后，当前没有独立的单调访问序列。

这是一张“每章最后位置”表，不是逐页访问日志。阅读同一章十次仍只有一条该章断点。重新访问旧章会让旧章成为这本书的最近阅读章。

### 3.3 manifests

每章保存一份 `ChapterPages` JSON，用于完整离线阅读及网络失败时回退。数据库没有 TTL 字段。在线获取策略由 `ReaderChapterLoader` 控制，不能把持久清单的存在当成图片签名仍然有效。

### 3.4 downloads

`state` 使用字符串 `queued / downloading / paused / complete / failed`，没有 SQL CHECK 约束。`created` 用于队列排序；重新入队通过冲突更新改变 state 和 error，保留原创建时间。`done` 是已完成页数，不是字节数。

`updateDownload(..., onlyIf)` 将旧状态条件放进 UPDATE 的 WHERE，避免已暂停或已删除任务被后台写回完成。error 最多保存 300 个字符。详情页中的漫画名称从 books 关联，任务 title 主要是章节标题。

## 4. JSON 格式

下面是结构示例，不是可直接请求的真实漫画地址或签名：

```json
{
  "id": "100", "title": "示例漫画", "cover": "",
  "author": "", "summary": "", "category": "", "latest": "",
  "chapters": [{"id": "200", "title": "第 1 话"}]
}
```

```json
{
  "book": "100",
  "chapter": {"id": "200", "title": "第 1 话"},
  "paths": ["/example/page-1.jpg", "/example/page-2.jpg"],
  "query": {"example": "placeholder"},
  "prev": "",
  "next": "201"
}
```

`prev`、`next` 的缺失状态写为空字符串，读取时转成 null。Manga 的非核心字符串使用 `optString`，章节数组缺失时可回退空列表；id、title，以及清单核心结构使用必填读取，不能认为任意损坏 JSON 都会被自动修复。JSON 目前没有独立格式版本号。

## 5. 偏好键字典

文件通过 `getSharedPreferences("settings", 0)` 打开。下面默认值指全新安装或字段不存在时的值。

| 键 | 类型 | 默认值 | 用途 |
| --- | --- | --- | --- |
| theme | String | system | system / light / dark |
| readingMode | String | vertical | vertical / ltr / rtl，分别为连续滚动、普通翻页、日漫方向 |
| dualPage | Boolean | true | 宽屏横向阅读允许双页 |
| preloadEnabled | Boolean | true | 是否启用后台预加载 |
| preloadPages | Int | 5 | 读写时限制在 3–5 |
| preloadWifiOnly | Boolean | true | 预加载仅允许当前默认网络为 Wi-Fi |
| searches | String | `[]` | JSON 数组，最近 8 条搜索 |
| notificationAsked | Boolean | false | Android 13+ 是否已经发起过通知授权请求 |

`notificationAsked=true` 表示已经请求过，并不表示用户授予权限。搜索数组解析异常回退空列表。设置写入使用 `apply()`：内存立即更新，磁盘异步提交。不要把该调用视为强制同步刷盘的事务。

## 6. 文件布局

```text
应用私有沙箱/
├── databases/
│   └── library.db             SQLite 及运行期可能出现的辅助文件
├── shared_prefs/
│   └── settings.xml           阅读与外观偏好
├── files/
│   └── chapters/
│       └── <book>/<chapter>/
│           ├── 0000.img       第 1 张图片
│           ├── 0001.img       第 2 张图片
│           └── page-*.part    写入中的临时文件
└── cache/
    └── images/                Coil 磁盘缓存，不是离线库
```

路径中的 book 和 chapter 必须匹配数字，页码必须非负。文件名数字至少补齐 4 位，扩展名 `.img` 不代表编码格式；实际按图片内容解码。`available` 只检查常规文件存在且长度大于零；下载时另有格式校验，但阅读时不会重新对所有文件做哈希校验。

## 7. 一致性与通知

- 多个 Store 数据修改方法用 `@Synchronized` 串行化进程内操作。
- 多章入队使用 SQLite 事务；`putBook` 在该事务之前执行。
- 完成图片的 rename 和删除任务共用 Store 锁，防止删除后后台又将临时文件提交成永久页。
- `revision: MutableStateFlow<Int>` 在修改后递增，通知 UI 重新查询；它不是数据库触发器，也不携带修改行详情。
- Store API 同步执行，部分 UI 路径会同步查库。现有规模下可用，但它不等于全部数据库操作都已经在 IO 调度器隔离。
- SQL 事务与文件系统操作不是同一个原子事务；异常退出仍可能留下临时文件或不一致状态，需要依据文件和任务状态排查。

## 8. 数据保留矩阵

| 操作 | 收藏／历史 | 设置 | 永久下载 | 临时缓存 |
| --- | --- | --- | --- | --- |
| 同包名、同签名覆盖升级 | 保留，前提是升级代码无破坏性迁移 | 保留 | 保留 | 不作为持久保证 |
| 删除某章下载 | 保留 | 保留 | 删除该章目录与任务行 | 不保证同步清除 |
| 取消收藏 | 取消收藏标记，历史保留 | 保留 | 保留 | 保留或自然淘汰 |
| 关闭预加载 | 保留 | 保存新偏好 | 保留 | 已有缓存可继续使用 |
| 系统清理缓存 | 保留 | 保留 | 保留 | 可能被清除 |
| 清除应用数据／卸载 | 删除 | 删除 | 删除 | 删除 |

`android:allowBackup="false"`，应用没有实现跨设备同步、导入导出或自建备份。不能把覆盖升级保留数据的能力解释为卸载后可以恢复。

1.3.3 不新增表或偏好键；readerChrome 是 ViewModel 会话状态，不写数据库。模拟器中正式签名 1.3.2 → 1.3.3 的覆盖安装核对了 10 个数据文件，安装前后哈希一致；新进程启动后四表数据、设置和 7 张测试下载图片保持一致。验证样本包含原有记录及专门添加的升级测试夹具，不代表所有未来迁移路径。

## 9. 迁移规则

当前 `onUpgrade` 直接抛出 `Missing database migration`。这不是自动清库策略，也不是已完成未来迁移支持。任何增加数据库版本的代码都必须先实现逐版本迁移并测试旧数据。

建议变更顺序：定义旧／新结构 → 准备旧版夹具 → 实现事务迁移 → 校验收藏、逐章页码、任务和文件映射 → 覆盖安装验证 → 更新本文。禁止为了绕过迁移错误而直接删除数据库。正式包名、数据库名、私有目录和签名是升级兼容性的共同约束。

## 1.3.4 更新器隔离存储

新增独立 SharedPreferences `updates`，保存 autoCheck 与 lastCheck；下载的安装文件和发布元数据存于 files/updates。它们不进入书库四表，也不改动原阅读偏好。升级后清理的是更新器自己的目录，详情见 [应用更新与安装](16-应用更新与安装.md)。实际系统覆盖安装后的书库保留记录见 [验证摘要](validation/v1.3.4-upgrade.json)。
