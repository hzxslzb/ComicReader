# 11 · 安全、隐私与性能边界

[返回文档中心](README.md) · 关联：[数据源](04-发现搜索与数据源.md)、[缓存](07-预加载缓存与网络策略.md)、[下载](08-下载与离线阅读.md)

## 1. 数据流与隐私

ComicReader 没有应用账号、自建后端或分析 SDK。书架、章节断点、搜索历史、设置和下载任务保存在本机；当前没有上传这些数据的同步接口。

联网搜索仍然会把搜索关键词提交给数据源，访问详情与章节会暴露所请求的作品／章节路径，图片请求会访问图片 CDN。远端服务能够观察正常网络请求包含的 IP、User-Agent、Referer 等信息。因此“不上传书架”不等于网络匿名，也不等于阅读内容对数据源不可见。

封面 URL 来自 HTML 解析结果；不能笼统声称所有请求只访问一个固定域名。章节图片构造使用 hamreus.com 子域，文本请求主要访问漫画柜移动站。

## 2. 无广告的实现方式

应用只提取目录、元数据与漫画图片，在原生 Compose 界面展示，不嵌入网页、不执行远程 JavaScript、不装载网页广告脚本。它没有运行一个通用网页广告过滤器。

如果原始漫画图片自身包含宣传页、水印或广告文字，它们仍是图片内容的一部分，不会自动被识别或裁掉。应用也不实现验证码绕过、付费内容解锁或登录会话抓取。

## 3. Android 权限

清单见 [AndroidManifest.xml](../app/src/main/AndroidManifest.xml)。

| 权限／配置 | 用途 | 边界 |
| --- | --- | --- |
| INTERNET | 搜索、详情、章节、图片 | 没有该权限就无法在线使用 |
| ACCESS_NETWORK_STATE | 读取默认网络能力、Wi-Fi 预加载策略 | 不读取 SSID 或位置 |
| POST_NOTIFICATIONS | Android 13+ 请求下载进度通知权限 | 用户可拒绝；已询问标记不代表已授权 |
| FOREGROUND_SERVICE | 前台下载服务 | 不保证服务永久运行 |
| FOREGROUND_SERVICE_DATA_SYNC | dataSync 类型服务 | 受系统相应限制 |
| WAKE_LOCK | 下载运行期间维持 CPU 工作 | 当前获取时带 6 小时超时 |
| allowBackup=false | 关闭应用声明的备份能力 | 应用也没有自建导入导出 |
| usesCleartextTraffic=false | 禁止普通明文 HTTP 流量 | 不能把 HTTP 地址当 HTTPS 失败后的降级路径 |

下载写应用私有目录，无需申请共享存储的全盘访问权限；没有相机、麦克风、通讯录、定位权限。MainActivity 对外导出以接收启动与漫画链接；DownloadService 不导出。

## 4. 输入与路径边界

当前防护分散在数据源、章节解码器和存储方法中：

- 浏览类型、分类路径和排序使用受约束模型构造，不直接把任意用户输入拼成浏览端点。
- 章节解码校验目标漫画／章节身份，防止错误页面被当作所请求章节。
- 解码只解析打包数据，不使用 JS 引擎执行下载到的脚本。
- 图片路径必须满足格式规则，拒绝包含 `..` 等越界路径形态；详情见解析代码。
- 下载目录的漫画与章节 ID 必须是数字，页码非负，阻止把这些字段作为自由文件路径。
- SQL 值使用参数绑定；表名和查询结构由代码固定。
- JSON 必填字段错误会失败，不会自动把所有错误内容转成空书架。

这些措施不等于完成了独立安全审计。修改解析器时必须继续检查长度、数量、解压输出和错误路径，尤其不能为了兼容新页面而加入 `eval`。

## 5. 资源限制表

| 区域 | 当前约束 | 说明 |
| --- | --- | --- |
| 文本 HTTP | 连接 15 秒、读取 25 秒、单次调用 40 秒 | 多次重试的总时长可能更长 |
| 文本长度 | 约 4,000,000 的检查 | 部分检查依赖 Content-Length，解码／发现另有字符长度检查；不是所有路径统一的严格流式字节配额 |
| 打包字典 | radix 2–62，条目数 1–100,000 | 章节解码输入校验 |
| LZ 解码 | 输入不超过 1,000,000，输出限制约 4,000,000，字典上限 200,000 | 防止异常解压无限增长；边界以代码比较运算为准 |
| 单章图片数量 | 1–3000 | 同时核对声明数量与实际路径列表 |
| 清单新鲜缓存 | 最多 3 份，120 秒 | 内存缓存，按插入顺序控制，不是通用 LRU |
| 图片临时磁盘缓存 | 150 MiB | Coil 管理，可被系统清理 |
| 后台预加载 | 提前 3／4／5 页 | 当前章不足时可接下一章；不是整书预取 |
| 永久下载单图 | 最大 60 MiB | Content-Length 和实际流式写入双重检查 |
| 下载并发 | 单个队列 worker | 一次处理一章，逐张落盘 |
| 下载页间间隔 | 120 ms | 不等于站点授权的请求额度 |

当前没有永久下载总容量上限、自动清理策略、磁盘剩余空间预留或每月流量统计。150 MiB 仅指临时图片磁盘缓存，不是应用总占用上限。清单数据库也没有自动按时间淘汰。

## 6. 重试与流量

章节文本最多尝试 3 次，对暂时性网络故障及 HTTP 408、500、502、503、504 使用有限重试，间隔 350 / 700 ms。403、404、429，以及 SSLHandshakeException／SSLPeerUnverifiedException 不按这一策略重试。图片加载和下载各有不同的镜像／重试策略，不应把章节文本规则套用于所有 HTTP 请求。

仅 Wi-Fi 限制的是后台预加载，不限制用户主动阅读或明确启动的永久下载。默认开启该限制；关闭后后台预取可使用移动网络。Wi-Fi 识别检查默认网络的 Wi-Fi transport 和 INTERNET capability，没有检查 VALIDATED；连接 Wi-Fi 但无法真正联网时，预加载仍可能尝试并失败。

关闭预加载会撤销后台等待者；如果前台已加入同一个章节请求，该共享请求仍保留。取消行为和竞态详见 [07](07-预加载缓存与网络策略.md)。

## 7. 图片与内存

Coil 负责常规解码和内存缓存；阅读请求依据视口提供尺寸，不对所有章节页一次性解码。1.3.3 的预加载只获取编码图片：命中磁盘缓存直接跳过，未命中时使用不解码 bitmap 的自定义 Decoder，并禁用内存缓存。显示时根据实际视口选择稳定尺寸档位；尺寸变化合并 180 ms 后调整，避免预取反复解码与缩放过程中逐帧重建请求。

纵向长图、超大图片、内屏双页和 4 倍放大仍可能增加内存压力。固定请求尺寸不等于所有图片类型的最终内存用量都完全相同。需要用实际长图和低内存设备测量，不能依据模拟器成功推出“不会 OOM”。

下载时用 BitmapFactory 的 bounds 检查可解码尺寸，避免为校验把整图解码到内存；随后阅读才按需加载。已落盘文件的完整性检查较轻，详见 [08](08-下载与离线阅读.md)。

## 8. 日志与公开问题报告

公开 Issue 可以包含版本、系统、设备、模式、复现步骤、公开漫画链接、HTTP 状态和异常类型。不要直接附个人 library.db、settings.xml、完整私有目录、签名文件或请求签名参数。

若需要网络证据，优先保留 host、路径类型、状态码、耗时和是否取消，删除查询中的临时签名。把“网页内容变化”“网络失败”“解析失败”“用户取消”分开统计，会比统一打印整个响应体更有帮助。项目当前没有完整的结构化诊断面板，这里是维护建议。

## 9. 升级前的风险核对

涉及包名、签名、数据库版本、图片缓存 key、文件路径或页码映射的改动都可能影响旧数据。应以可恢复夹具做覆盖升级验证，不使用用户唯一的数据副本做破坏性实验。新权限、遥测、外部服务或数据导出功能都需要重新说明数据流，不能沿用本版“完全本地书架”的描述而不核查实现。
