# 14 · 故障排查与维护手册

[返回文档中心](README.md) · 关联：[数据源](04-发现搜索与数据源.md)、[阅读与预取](07-预加载缓存与网络策略.md)、[下载](08-下载与离线阅读.md)

## 1. 先确定故障层级

| 看到的现象 | 优先检查 | 不应直接得出的结论 |
| --- | --- | --- |
| 搜索／发现整页失败 | 站点请求、HTML 选择器、响应类型 | 不是“所有漫画都不存在” |
| 章节整页网络异常 | 章节 HTTP、解码、请求代次与取消 | 还没到图片 CDN 加载阶段 |
| 页码正常但某图失败 | 图片请求、签名、CDN、本地文件 | 不一定是章节清单获取失败 |
| 一直 loading 或新章被旧状态覆盖 | readerGeneration、旧 finally、取消传播 | 不要只增加超时时间 |
| 下载失败 | 任务状态、网络、图片校验、磁盘落盘 | 不等于收藏／历史丢失 |
| 有缓存但离线打不开 | 是否完整永久下载、是否有清单 | 临时缓存不是离线保证 |
| 更新后像空书架 | 包名、签名、是否 Debug、是否清数据 | 不应立即宣称数据库迁移丢失 |

建议收集版本、Android 版本、机型、模式、是否双页、网络类型、公开漫画／章节链接、最后成功步骤、首次失败步骤。区分“任何书都复现”和“某个章节复现”能快速缩小范围。

## 2. 滑动切下一章时整页异常

当前重点检查四个环节：

1. 末页手势是否真正触发了正确的 nextId，而不是错误章节。
2. `AppViewModel.read` 是否为此次请求创建新的代次，并让旧请求的完成／异常／finally 不再覆盖新状态。
3. `ReaderChapterLoader` 是否让前台加入已有预加载，再取消旧预取；共享请求是否仍有等待者。
4. 章节 HTTP 是否成功、响应是否能解码为匹配 ID 的 ChapterPages。

1.3.1 已修复过“取消旧请求后旧 finally 清除新 loading”的竞态，并加入共享预取与有限网络重试。回归时应分别验证按钮切章、末页手势切章、快速连续切换、预加载开／关和下一章已有历史。

不要把所有异常都吞掉并显示空章，也不要把 CancellationException 转成“网络异常”。预加载失败不应把当前正在阅读的章节变成错误页；实际打开下一章时仍可以重新尝试。

对应源码：[AppViewModel.kt](../app/src/main/java/com/arnolee/moye/AppViewModel.kt)、[ReaderLoading.kt](../app/src/main/java/com/arnolee/moye/ReaderLoading.kt)、[MangaSource.kt](../app/src/main/java/com/arnolee/moye/MangaSource.kt)。

## 3. 章节 HTTP 与解析

| 证据 | 解释与处理 |
| --- | --- |
| 超时／短暂 IO 异常 | 查看网络与站点状态；当前章节路径有有限重试 |
| HTTP 408 / 500 / 502 / 503 / 504 | 当前最多 3 次尝试，保留最终失败证据 |
| HTTP 403 | 访问被拒绝；不无限重试、不绕过访问控制 |
| HTTP 404 | 页面不存在或链接／结构变化；核对章节 ID |
| HTTP 429 | 限流；当前不按章节瞬时错误自动重试，稍后再试 |
| TLS 异常 | 核对网络环境与证书错误，不关闭证书校验来“修复” |
| 200 但不是预期 HTML | 可能是挑战页、错误页或站点结构变化 |
| 解码 ID 不一致 | 拒绝错误章节；保留脱敏样本定位解析问题 |

排查时使用公开 URL 和适量请求即可。不要连续批量扫全站来定位一个稳定复现问题。修复解析器的标准过程是保存适当脱敏夹具、补失败单测、最小修改、验证代表页面。

## 4. 图片“暂未加载”

先确认页码与清单已经出现。检查该页来源是永久本地文件还是网络 URL，再看请求状态、图片格式和当前清单是否可能包含过期签名。

图片服务有镜像尝试，手动重试也会调整候选服务器。镜像不能修复过期的所有查询参数或站点返回的错误图片路径。清单持久缓存用于失败回退，但不保证签名一直有效；在线重新打开章节可触发清单刷新路径，具体受 120 秒内存缓存控制。

如果本地文件被认为 available（非空）但已损坏，现有读取并不自动逐页校验并替换。可删除**该章下载任务**后重新下载；该操作会删除该章图片，但保留收藏和阅读历史。先确认需要重下的章节，不要清除整个应用数据。

## 5. 预加载不生效或流量异常

依次检查：

1. 主设置／阅读设置是否开启预加载，页数是否为 3、4 或 5。
2. “仅 Wi-Fi”是否开启；当前默认网络是否具备 Wi-Fi transport 和 INTERNET capability。
3. 当前页是否接近章末；窗口只向后预取，最多延伸到下一章，不无限预取整书。
4. 预取图片是否已经在缓存中；缓存命中可能没有新的网络请求。
5. 是否已经进入后台、离开阅读页或更改偏好，从而停止预取；1.3.3 翻页只增量更新窗口，不再全部取消重建。

VPN 可能影响默认网络能力展示；实现没有检查物理底层所有网络，也不读取 SSID。Wi-Fi 连上但无互联网时可能仍满足 capability 条件，因此“允许尝试”不代表实际加载成功。

“仅 Wi-Fi”只约束预加载。用户主动翻页、在线阅读和启动下载仍可能使用移动网络。关闭预加载不会删除已经缓存的图片，也不会取消有前台等待者的共享章节请求。

## 6. 末页再滑没有切章

- 必须在一次新的手势开始时就已经位于稳定末页；把页面滑到末尾的那次手势不会直接跨章。
- 纵向向上、普通横向向左、日漫横向向右才是下一页方向。
- 需要超过距离阈值，并明显沿主方向滑动；小拖、斜拖、点击不会触发。
- 双指手势和横向放大拖动不能被当成跨章。
- 横向翻页需要 pager 停稳且未处于放大拖动状态。
- 最后一章没有 nextId 时停留原处。

纵向还需检查最后图片是否已经完整到达视口底部条件，列表是否仍在滚动或调整缩放锚点。用 [ChapterAdvanceTest](../app/src/androidTest/java/com/arnolee/moye/ChapterAdvanceTest.kt) 的分阶段操作复现，比持续猛滑更能定位问题。

## 7. 下载暂停、停住或“完成”却缺图

应用启动会把遗留 queued/downloading 标记为 paused，用户需要手动继续。下载服务不是开机自动恢复的持久调度器。系统可能终止前台服务；代码也处理服务超时，但不保证后台无限运行。

暂停通过状态检查协作生效；如果正在阻塞的网络读尚未返回，UI 标记暂停与网络调用真正退出可能有时间差。续传以已完成的整张图片为单位，未完成图片重新下载，不支持 HTTP Range 的字节断点。

“complete”任务如果被外部因素破坏了文件，不会仅因再次 enqueue 自动重新下载，因为入队会跳过 complete。先核对缺图，再删除该章任务并重新下载。删除之后历史不应消失；若消失，应按 Store 操作追查，而非认为它是正常清理行为。

空间不足、临时文件提交失败、返回内容不是图片都会导致失败。`page-*.part` 是临时文件，不是可直接阅读的已完成页。不要手动把它改名为 `.img` 来伪造完成。

## 8. 历史记录看似不正确

- UI 第 N 页对应数据库 page=N-1。
- 双页显示一组不等于历史页码只有组号；展开／收起需保留具体原页。
- 各章各留一条最新断点，继续阅读取本书最后访问章；重新访问旧章后从旧章继续是当前设计。
- 纵向历史不保存长图内部像素偏移，重新进入从该图片位置恢复。
- 缩放倍率不写入历史，重新进入默认尺寸不等于章节断点丢失。
- Debug 与正式版的数据隔离；卸载或清除数据会删除本地库。

## 9. 开发者诊断命令

以下命令用于已连接的专用开发设备。先确定设备序列号；多设备时为 adb 增加 `-s <serial>`，不要误操作用户设备。

```sh
adb devices
adb shell dumpsys package com.arnolee.moye.debug
adb shell wm size
adb shell wm density
adb logcat -d -t 300
```

logcat 可能含其他应用信息，分享前仅提取相关异常并脱敏。设备 UI 测试后若显示配置未恢复，可在专用模拟器执行 `adb shell wm size reset` 与 `adb shell wm density reset`；网络状态也应恢复到测试前状态。

不提供通用“删除数据库修复”命令。需要检查本地数据时优先使用测试包和可重建夹具，不上传真实用户库。

## 10. 维护闭环

每次修复记录：现象 → 最小复现 → 请求／状态时间线 → 根因 → 修改点 → 回归用例 → 未验证范围。如果只有猜测，应明确标为待验证；不要用“优化网络”概括一个实际是协程取消竞态的问题。

修复完成后同步对应 Doc 章节、CHANGELOG 和实际测试记录。数据源改版、系统行为变化和新设备适配应各自保留证据，不把所有失败归入同一个“网络异常”。
