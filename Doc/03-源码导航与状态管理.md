## 3. 页面状态

`screen` 取 `home / detail / reader`，`tab` 决定主页内容。MoyeApp 用 when 分支切换页面，并在 screen 非 home 时接管返回键。阅读器不使用导航路由字符串、NavController 或 back-stack destination。

`selected` 保存当前漫画；`activeChapter` 是正在打开的章节；`pages` 是已成功得到的章节清单。两者可能在加载期间暂时不同时拥有值：新章打开时先设置 activeChapter，并把 pages 置空。

| 阅读字段 | 含义 |
| --- | --- |
| readerLoading | 当前有效阅读请求正在等待 |
| readerError | 当前有效请求的错误文本 |
| readerStart | 打开章节时从数据库恢复的初始页 |
| readerPage | 当前规范化单页索引，单双页模式共用 |
| readerGeneration | 阅读请求代次，不持久化 |
| readerJob | 当前前台等待协程 |
| preloadJob / preloadKey | 当前后台预取窗口及去重键 |

UI 在 pages 为空时依据 readerLoading 显示加载状态，否则展示 readerError 或默认不可用提示。pages 非空时建立按漫画与章节 ID 分组的 ReaderContent。

## 4. 请求取消的不同语义

- `searchJob`：新搜索取消旧搜索协程，新的关键词重新建列表；更多结果使用 submittedQuery，避免输入框编辑影响正在翻页的查询。
- `detailJob`：切换作品或返回主页时取消；已有本地目录可作为失败时回退。
- `readerJob`：只控制当前前台等待，不意味着可以无条件终止其他人共享的清单请求。
- `preloadJob`：窗口、设置或网络变化时取消；如果清单仍有前台等待者，底层请求继续。
- `DownloadService.worker`：属于服务，不由阅读页返回动作取消。

章节 get 使用 Flight.readers 计数。read 启动前台 join 后才释放上一轮预加载等待者，以防“准备切入已预取章节”时先把共享请求取消。

## 5. 持久状态与瞬时状态

写进数据库／偏好的内容：收藏、书籍完整详情、逐章页码、清单、下载队列及其状态、主题、方向、双页、预加载、搜索历史。

仅在内存中的内容：请求 Job、当前加载错误、首页结果、搜索结果、清单新鲜度时间、当前预取窗口、页面选择与部分布局状态。内存信息在进程死亡后不能依赖仍存在。

AppViewModel 没有使用 SavedStateHandle。若未来要求系统回收进程后自动回到原来的章节页面，需要额外定义恢复协议，而不是仅增加 rememberSaveable。

## 6. revision 的使用约定

store 修改数据后递增 revision。MoyeApp collectAsState 后把 revision 传到页面；页面以 `remember(revision, ...)` 重新查询书架、历史或任务。它同时被多种写操作触发，包括 putManifest，因此“revision 变了”不等于“阅读进度变了”。

避免在 Composable 每次重组时写入数据库，否则可能出现写库 → revision → 重组 → 再写库的循环。进度写入应放在事件、snapshotFlow 或明确的生命周期回调中。

## 7. 新增功能的落点

- 一个新的本地开关：定义偏好字段与默认值 → ViewModel 更新方法 → 共用设置控件 → 验证保存和重建。
- 一个新的网站栏目：先增加 BrowseKey / URL 与解析测试，再接状态和 UI。
- 一个新的阅读模式：先定义原始页索引如何映射，后接布局；不要直接把历史单位改成组号。
- 一个新的下载状态：同时更新队列处理、stateLabel、恢复流程、删除条件及测试，不能只改显示文字。

注意：搜索与详情的旧任务 finally 仍共享 loading 布尔字段，没有照搬阅读请求的 generation 隔离。扩展这些路径时应针对快速切换加入回归，而不是认为整个应用已经统一采用代次机制。
