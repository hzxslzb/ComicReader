# 04 · 发现、搜索与数据源

[返回文档中心](README.md) · 基线：1.3.2

## 1. 数据源契约

唯一内置站点为 `https://m.manhuagui.com`。下面的地址是当前解析器使用的页面协议，不是源站对本项目承诺的公开稳定 API。源码中用固定 User-Agent 和 Referer 发起 HTTPS 请求，然后提取数据，绝不把抓到的脚本交给 JavaScript 引擎运行。

| 用途 | 方法与地址 | 主要参数／Referer |
| --- | --- | --- |
| 首页 | GET `/` | 默认 Referer 为站点根地址 |
| 搜索第一页 | GET `/s/{编码关键词}.html` | UTF-8 URL 编码，空格为 `%20` |
| 搜索后续页 | POST 同一个搜索地址 | FormBody：page、ajax=1、order=0、key |
| 漫画详情 | GET `/comic/{bookId}/` | bookId 只接受数字 |
| 章节清单 | GET `/comic/{bookId}/{chapterId}.html` | Referer 为该漫画详情页 |
| 漫画大全首页 | GET `/list/` 或 `/list/{category}/` | 默认按添加时间 |
| 漫画大全排序首页 | GET 上述目录下 `update.html` 或 `view.html` | 对应更新时间、浏览次数 |
| 大全后续页 | GET 分类目录 | page、ajax=1、order、catid=0 |
| 最近更新／排行榜首页 | GET `/update/`、`/rank/` | 无交叉分类 |
| 更新／排行后续页 | GET 同目录 | page、ajax=1、order=1 |

源站的某些结果仅含 HTML 片段，不能要求每次都有完整 html/head/body 或第一页分页元素。

## 2. 首页与分类解析

`DiscoverSource.parseHome` 读取 `#topSlider a[href]` 作为横幅，从 `.main-list` 读取栏目，并用前一个兄弟元素中的 h2 取得栏目标题。条目链接严格匹配 `/comic/数字/`；封面优先 data-src，再回退 src。标题、作者、分类、最新章来自该条目本身。

首页栏目不是硬编码的四个类名，按解析到的列表生成 HomeSection。1.2.0 实测样本是 5 个横幅、4 个栏目、各 12 本；UI 每批展示 6 本，因此“换一批”是在已抓取集合中切片，不是另一个网络接口。

分类从 `#popCat2 a[href]` 动态读取，slug 去重。分组逻辑：空串／lianzai／wanjie 为连载状态；已知 6 个地区 slug 为地区；已知 5 个读者群 slug 为读者群；其他合法 slug 归入题材。当前样本共 52 项，不应把这个数量写成永远不变的产品上限。

## 3. 列表 URL 与分页状态

BrowseKey 包含 kind、category、order，是请求与状态的联合键。构造时限制：kind 只能 list/update/rank；分类只允许小写英文字母；order 只能空串/update/view；update/rank 不允许附带分类或排序。

示例：

```text
kind=list, category=rexue, order=view, page=1
https://m.manhuagui.com/list/rexue/view.html

同筛选第 2 页
https://m.manhuagui.com/list/rexue/?page=2&ajax=1&order=view&catid=0

排行榜第 2 页
https://m.manhuagui.com/rank/?page=2&ajax=1&order=1
```

每个 BrowseKey 有独立 BrowseState。加载更多成功后合并 entries，并以漫画 ID 去重；只有请求成功才推进 page。若后续片段省略 totalPages，保留此前得到的总页数。hasMore 同时检查本页非空和页数／条目数量条件。

刷新时保留旧内容，成功后替换；失败显示 InlineError。retryMore 记录失败是否发生在追加页，避免用户点击重试后错误回到第一页。原站当前更新与排行各为 5 页／100 本；应用按返回元信息判断，不提供人为生成的周榜／月榜。

## 4. 搜索行为

search 对输入先 trim，空串不发请求。若匹配支持的漫画链接，直接提取 ID 并打开详情。否则新搜索清空旧结果、保存 submittedQuery；加载更多使用 submittedQuery，不读取后来被改过的输入框。

成功搜索后，把关键词放到最近历史最前面、去重并保留 8 项，以 JSON 数组保存。解析搜索条目时要求 h3 标题及漫画链接；支持 data-src 延迟封面。pageCount 优先决定是否还有下一页，没有时以条目数至少 20 作为回退判断。

当前搜索错误面板的“重新试试”调用普通 search，意味着重新搜索第一页；它和发现列表的 retryMore 保留追加语义不同。维护时不要把两条路径描述成相同恢复策略。

链接识别支持 m./www./无子域名的 manhuagui HTTPS 漫画路径；Android Manifest 的外部 Intent 过滤器只声明 m. 和 www. 两种域名。解析器能识别的输入范围与操作系统自动分发范围不是完全同一件事。

## 5. 漫画详情

parseDetail 必须找到 `.book-detail`，从 `#chapterList a[href]` 提取当前漫画下的数字章节链接，去重后反转为应用阅读顺序。这样做依赖目前源站目录采用相反的展示顺序；若站点改为分组、分卷或改排序，必须重新验证，不可仅凭 ID 大小排序。

作品标题优先 h1，缺失时从 title 文本回退；作者、类别、更新信息按 dl/dt/dd 文本匹配。无章节时抛出错误，不把缺目录的页面默认为成功。

## 6. 章节解码

ChapterDecoder 仅处理已知数据格式：

1. 限制 HTML 字符串长度小于 4,000,000。
2. 若找到打包形式，取 payload、radix、词条数量和字典。
3. radix 必须在 2–62，词条数量在 1–100,000。
4. 字典已含 `|` 时直接拆分，否则调用 LzBase64 解压，再拆分。
5. 通过基数编码构造替换表，对 payload 中词边界 token 做数据替换。
6. 截取 JSON 对象；非打包页面尝试 `SMH.reader({...})` 格式。
7. 校验 bookId、chapterId 与请求一致；图片数必须 1–3000 且与 count 相等。
8. 图片路径必须以单 `/` 开头，拒绝 `//` 和 `..`；提取 sl 查询参数以及非零数字上下章 ID。

LzBase64 只接受 Base64 字母表，限制输入长度、输出长度和字典大小，截断数据会抛异常。它不是通用脚本解释器，也不执行 eval。伪装成 200 成功页的验证页通常在结构或解码校验阶段失败。

## 7. 网络错误差异

搜索／详情使用同步 execute 的 IO 包装；发现页面也是同步请求。章节使用可取消的异步 Call，并对连接类 IOException 和 408/500/502/503/504 最多发起 3 次请求，退避为 350 ms、700 ms。403/404/429、证书握手和证书主机校验错误不按这条逻辑重试。

解析错误不属于“多请求一次必能解决”的情况。发生格式变更时应修解析器、增加样本测试；不要把重试次数调高来掩盖数据不匹配。

## 8. 维护数据源的流程

保留问题 URL 与错误类型 → 区分 HTTP 错误／挑战页／格式变化 → 只获取最小必要公开样本 → 删除 Cookie、令牌或个人字段 → 加入 test/resources → 写解析回归 → 修改选择器或解码器 → 复跑相关单元与真实数据集成流程。不要为了使测试通过就宽松接受空章节或不同漫画 ID。
